# NIPPONFERRY V18 — 공식 운항정보 변경 감시 및 안전 갱신

기준: 2026-10-14. 기존 45편을 유지하고 신규 SEO 페이지는 생성하지 않는다.

## 1. 자동 감시
- 워크플로: `.github/workflows/v18-official-source-watch.yml`
- 실행: 매일 01:23 UTC (한국시간 10:23), 수동 실행, 감시 코드 변경시
- 입력: `scripts/v17-official-sailings.json`의 15개 항만 공식 `scheduleSource` URL
- 공식 페이지/PDF의 전체 문서 해시(SHA-256)를 이전 성공 실행의 저장된 아티팩트와 비교
- 첫 실행은 기준 스냅샷을 생성한다. 조회 실패 시 경고를 남기고 이전 정상 해시를 보존
- 결과는 Actions 아티팩트 `v18-official-source-snapshot` (90일), `report.json`에 저장
- 문서가 변경됐거나 조회 실패 시 GitHub Issue 생성/추가 코멘트 (미해결 항목 중복 생성 방지)

## 2. 자동화의 한계
- 바이트 변경은 일정/부두/선박 변경을 뜻하지 않는다. 공지 디자인, 업데이트 표시, 동적 응답만 바뀌어도 경고가 날 수 있다.
- 바이트가 동일하다고 운항이 확정된 것은 아니다. 웹 페이지 밖의 별도 공지/선사 안내를 확인해야 한다.
- 이전 아티팩트가 없어지면 새 기준선부터 다시 설정되므로 역사적 변경을 소급 탐지하지 않는다.
- 예약·로그인 필요한 공식 검색 시스템, 자바스크립트 동적 결과, 차단된 PDF 등은 별도 사람이 조회해야 한다.
- GitHub Actions 실행 시간은 부하·비활성화 등에 따라 지연/누락될 수 있다.
- 이 감시 도구는 실시간 항차 확인, 자동 운항정보 수집, 자동 공개 게시 기능이 아니다.

## 3. 변경이 감지되면
1. GitHub Issues의 `V18 official source changes — manual review required`에서 관련 run 보고서 확인.
2. 해당 항만의 공식 원문 및 수정일/취소 공지 확인. 예정 선석과 실제 승객 동선, 귀선 마감을 구분.
3. 항차별 날짜·선박명·접안 부두·입출항 예정 시각이 근거로 검증되는 경우에만 `scripts/v17-official-sailings.json` 갱신.
4. `python3 scripts/v17-ops-apply.py` 실행 후 기존 45편 변경 diff 검토.
5. `V17 Official Calls Live QA` 실행 후 180개 검수의 `summary.json`에서 `failed=0` 확인.
6. 최종 공개 사이트에서 최신 기준일·취소·변경·안전 경고 검토.

## 4. 반드시 미확인으로 남길 정보
- 실제 승객 게이트 및 출입허용 여부
- 항차별 전용 셔틀 운행/막차
- 게이트에서 시설 정문까지 실측 시간
- 선사에서 공지하는 최종 승객 귀선 마감시각

위 수치는 확인 없이 지도 예측이나 출항 예정시간으로 대체하지 않는다.
